# 贡献指南

> English: [Contributing](../CONTRIBUTING.md)

BangumiToday 是仍在开发中的个人 Flutter 桌面项目，欢迎问题反馈、文档修正和范围明确的
Pull Request。参与交流请遵守[行为准则](../CODE_OF_CONDUCT.md)，安全漏洞请通过
[安全策略](../SECURITY.md)中的私下渠道报告。

## 开始之前

- 先搜索已有 Issue 和 Discussion。可复现的错误和具体功能请求请使用
  [Issue 模板](https://github.com/BTMuli/BangumiToday/issues/new/choose)。
- 较大的新功能、架构调整或原生依赖引入，请先与维护者讨论方向，再投入实现。
- 基于仓库默认分支 **`master`** 创建分支，Pull Request 也以 `master` 为目标。
  每次改动保持目标明确，说明目的和验证结果。
- 错误报告请提供应用版本、操作系统和安装方式。日志需隐去 Token、私人 RSS 地址和
  个人路径；必要的崩溃转储通过私下渠道提供。

## 开发环境

当前验证基线为 **Flutter beta `3.49.0-0.2.pre`**，与
[`pubspec.yaml`](../pubspec.yaml) 和[发布工作流](../.github/workflows/release.yml)一致。
Dart 约束为 `>=3.9.0 <4.0.0`，使用 Flutter 自带的 Dart SDK。
低于声明下限的 Flutter 版本不受支持。

Windows x64 是当前打包发布目标。仓库保留 macOS runner，但没有 macOS 发布工作流。
Linux、移动端和 Web 不是当前项目目标。Windows 构建需要 Visual Studio 的
**使用 C++ 的桌面开发**工作负载、Windows SDK、CMake 和 vcpkg。
原生构建会查找 `VCPKG_ROOT`、`VCPKG_INSTALLATION_ROOT` 或 Visual Studio 自带的 vcpkg。

可以先 fork 仓库，再克隆并安装依赖：

```shell
git clone https://github.com/BTMuli/BangumiToday.git
cd BangumiToday
git submodule init
git config submodule.repos/bt_download.url https://github.com/BTMuli/bt_download.git
git submodule update --init --recursive
flutter pub get
dart run husky install
```

[`.gitmodules`](../.gitmodules) 中的子模块地址使用 SSH。上述本地配置覆盖允许没有
GitHub SSH 密钥的贡献者通过 HTTPS 初始化子模块，不会修改 `.gitmodules`。
已配置 SSH 时，直接使用 `--recurse-submodules` 克隆即可。
已有仓库也需在构建前初始化子模块。

从 `master` 创建主题分支；本工作区中的 Agent 创建分支时使用 `codex/` 前缀。

## OAuth 配置与运行

在 [Bangumi 开发者设置](https://bgm.tv/dev/app)创建应用，将回调地址设置为
`BangumiToday://oauth/bangumi/callback`，与
[`app_constants.dart`](../lib/core/constants/app_constants.dart)保持一致。
在项目根目录创建已被忽略的 `.dart-define.json`：

```json
{
  "BANGUMI_APP_ID": "your-app-id",
  "BANGUMI_APP_SECRET": "your-app-secret"
}
```

这些值通过构建参数注入。Flutter 不会在运行时读取 `.env`，构建参数注入也不能保证
桌面二进制中的密钥无法被提取。不要提交凭据或签名私钥。

首次在 Windows 运行或构建前，先准备固定版本的播放器资源：

```powershell
./scripts/prepare_playback_inference.ps1
flutter run -d windows --dart-define-from-file=.dart-define.json
```

准备脚本下载并校验基础推理资源及 SDK 头文件，输出到 `.dart_tool/playback_inference/`。
CMake 会检查资源并编译原生垫片，不会替你准备缺失的推理资源。
完整 NVIDIA TensorRT 运行组件由用户在设置页另行安装。

未设置 `BT_DOWNLOAD_RUNTIME_DIR` 时，Windows CMake 还会自动构建并安装
`bt_download` 子模块的 Release runtime，再随 runner 打包；Debug/Profile 构建也使用
该引擎。首次构建耗时可能较长。自动查找 vcpkg 失败时，请设置 `VCPKG_ROOT`。

macOS 开发需要 macOS 主机和对应的 Flutter 桌面工具链：

```shell
flutter run -d macos --dart-define-from-file=.dart-define.json
```

随包下载引擎、Windows 系统代理接入和原生 Anime4K/AnimeJaNai 播放增强仅适用于 Windows。
仓库有 macOS 源码不代表功能完全一致，也不代表已验证 macOS 安装包。

## 代码位置

| 路径 | 职责 |
| --- | --- |
| `lib/pages/` | 功能页面及仅该页面使用的组件 |
| `lib/widgets/` | 多页面共享的组件 |
| `lib/data/`、`lib/domain/`、`lib/request/` | 仓储、解析与网络访问 |
| `lib/models/` | 数据模型与生成的序列化代码 |
| `lib/database/drift/` | SQLite 表结构、生成数据库与迁移 |
| `lib/database/app/`、`lib/database/bangumi/` | 数据库存取 |
| `lib/providers/`、`lib/store/` | Riverpod 组装与应用状态 |
| `lib/core/` | 共享服务、配置与工具 |
| `windows/playback/` | Windows 渲染器与推理接入 |
| `repos/bt_download/` | C++ 下载引擎子模块 |
| `test/` | 长期维护的功能回归测试和数据 |

修改 JSON 模型或 Drift 表结构后，请重新生成并包含相关已跟踪的产物：

```shell
dart run build_runner build --delete-conflicting-outputs
```

数据库改动需保留对现有安装的迁移。应用与 `bt_download` 作为同一版本发布，协议改动
必须同步修改两端，不为不匹配的客户端或引擎添加猜测式兼容。
AniBT 相关工作请使用 [AniBT 技能](../.agents/skills/anibt/SKILL.md)及当前官方 API 文档。

## 代码规范与验证

遵守 [`analysis_options.yaml`](../analysis_options.yaml) 和 [`AGENTS.md`](../AGENTS.md)。
`dependencies`、`dev_dependencies`、`dependency_overrides` 中的包名分别按字母顺序排列，
保留版本、来源配置和相关注释。UI 控件沿用邻近样式，保持操作直接可见，
具体交互规则以 `AGENTS.md` 为准。

Dart 改动按受影响范围进行格式检查与静态分析。检查整个 `lib` 的命令为：

```shell
dart format --output=none --set-exit-if-changed lib
dart analyze --fatal-infos --fatal-warnings lib
```

功能行为变化时运行相关功能测试。例如，已维护的评论解析回归测试为：

```shell
flutter test test/bangumi/comment_parser_test.dart
```

长期维护的功能回归测试与数据放在 `test/`。一次性验证脚本、数据及输出统一放在
`temp/` 下用途明确的子目录中，验证后删除，不提交临时验证文件。
默认不编写 UI 交互测试，界面验收由开发者手工执行。

仅修改文档时检查链接和内容，无需构建应用。完整构建、启动应用和 UI 手工检查由开发者
按需执行；Agent 只有在用户明确请求时才能执行。仓库当前没有 PR/默认分支的质量检查
工作流，tag 打包也不会运行 Dart 分析或功能测试，因此 PR 中要如实说明实际执行的检查。

## Windows 打包（手工执行）

原生 runtime 是 Windows 包的一部分。如需复用单独构建的引擎，将
`BT_DOWNLOAD_RUNTIME_DIR` 指向**完整安装目录**，不要指向构建目录或只复制
`bt_download.exe`。必须保留 DLL、MSVC runtime、许可、NOTICE 和 SPDX SBOM。

Windows 构建后可校验 bundle，路径中的配置应与实际构建一致：

```powershell
./scripts/verify_windows_bundle.ps1 `
  -BundlePath build/windows/x64/runner/Release `
  -EngineRuntimePath $env:BT_DOWNLOAD_RUNTIME_DIR
```

未设置该环境变量时省略 `-EngineRuntimePath`；提供它时，还会逐文件比较引擎源 runtime
的 SHA-256。原生资源与第三方说明见[播放器接入](../windows/playback/README.md)和
[推理资源准备](../windows/playback/inference/README.md)。当前 Windows libmpv 二进制
为 GPL 构建。

本地 MSIX 发布脚本 [`dev_build.ps1`](../dev_build.ps1) 从被忽略的 `.env` 读取
`SIGN_SECRET` 和四段式 `MSIX_VERSION`，使用本地 `BTMuli.pfx`。
OAuth 配置优先读取 `.dart-define.json`，文件不存在时才从 `.env` 读取。
脚本准备播放器资源、构建或复用引擎、验证 bundle，再生成 MSIX。
`-SkipInstall -SkipFirewallRule` 可跳过安装询问和防火墙注册；临时
`build_config.json` 在 `finally` 中删除。

[`v*.*.*` tag 工作流](../.github/workflows/release.yml)构建 Windows ZIP、MSIX 和
Store-MSIX，并创建 GitHub Release **草稿**。CI 使用 `BANGUMI_APP_ID`、
`BANGUMI_APP_SECRET`、`MSIX_CERTIFICATE_BASE64`、`SIGN_SECRET` Secrets；
导出的 `BTMuli.cer` 是不含私钥的公钥证书。生成 Store 产物不会自动发布到微软商店。

引擎测试需主动启用，不进入上述两条发布路径。需要时由开发者在 `repos/bt_download`
中手工执行：

```shell
cmake --preset windows-x64-debug-tests
cmake --build --preset windows-x64-debug-tests
ctest --preset windows-x64-debug-tests
```

## 提交与 Pull Request

提交信息不限制语言，简洁说明改动目的即可。推荐使用
[Gitmoji](https://gitmoji.dev/) 的 `<emoji> <description>` 风格，例如
`📝 修正贡献指南`，不作为强制要求。emoji 按实际变更目的选择，可参考
[选择说明](../.agents/skills/gitmoji-commit/references/emoji-selection.md)。

每个提交保持单一目的。已安装的 pre-commit 钩子会排序 import、分批格式化已跟踪的
Dart 文件并运行 `lint_staged`，可能改到本次未编辑的文件，执行后应检查工作区。
大量已暂存 Dart 改动可能使 `lint_staged` 占用较多资源，可按独立目的拆分提交，
不要因为文件数量阈值而机械地改写历史。

Agent 完成授权改动后必须停留在工作区；只有用户明确要求时，才可提交、amend、rebase、
cherry-pick、revert 或 push，具体要求以 `AGENTS.md` 为准。

Pull Request 以 `master` 为目标，说明问题、修改后的行为、关联 Issue、验证结果及限制，
并包含相关文档和生成文件。涉及 UI 时，可附开发者提供的截图，说明尚待手工验收的项目。
