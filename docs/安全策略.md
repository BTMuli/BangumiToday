# 安全策略

> English: [Security Policy](../SECURITY.md)

## 支持的版本

BangumiToday 仍处于开发阶段。安全修复面向最新公开发布版本，在 `master` 分支开发。
旧版本没有独立的安全维护分支；确认问题时，请先更新并检查是否仍可复现。

| 版本 | 安全维护方式 |
| --- | --- |
| 最新公开发布版本 | 通过后续更新提供修复 |
| 旧版本 | 不单独回移修复 |
| 尚未发布的 `master` 构建 | 用于开发，不保证稳定性 |

本项目由个人维护，没有专职安全响应团队，也不承诺固定的响应或修复时限。

## 私下报告漏洞

请发送邮件至 [BTMuli](mailto:bt-muli@outlook.com)：**bt-muli@outlook.com**，
标题可使用 `BangumiToday 安全漏洞报告`。

仓库当前未启用 GitHub 私密漏洞报告功能，请使用邮件。不要在公开的 Issue、Discussion
或 Pull Request 中发布利用细节、凭据或私人数据。普通错误和功能建议请使用
[Issue 模板](https://github.com/BTMuli/BangumiToday/issues/new/choose)。

报告中请尽量包含：

- 应用版本、操作系统及安装方式（商店、MSIX、ZIP 或源码构建）。
- 受影响的组件、可能造成的影响和触发条件。
- 使用虚构数据的最小复现步骤或概念验证。
- 已脱敏的相关日志片段，以及可联系到你的方式。

维护者会评估报告，必要时补充询问信息，并与报告者协调修复及公开时间。
请在协调后再公开可直接利用的细节。不要未经授权使用他人的账号或第三方服务验证漏洞。

## 适用范围与数据处理

报告范围包括 Flutter 应用、OAuth 与应用链接、本地存储、RSS/种子解析、随包的
`bt_download` 引擎、Windows 播放组件及打包脚本。涉及上游依赖时，请注明受影响版本，
便于判断修复应落在本仓库还是上游。Bangumi、RSS 提供方及镜像站的可用性与站点政策
由相应服务负责。

- `BANGUMI_APP_ID` 和 `BANGUMI_APP_SECRET` 通过 Dart 构建参数注入。
  配置文件不进入 Git，并不意味着桌面二进制中的值无法被提取。
- Bangumi OAuth Token 和蜜柑订阅 Token 优先使用系统安全存储。
  旧数据迁移或安全存储失败时，仍可能保留或写入 SQLite 回退路径，不能保证所有凭据
  均以加密形式落盘。
- 应用配置、订阅、本地路径、收藏和播放进度保存在本地 SQLite/Hive 中。
  私人订阅地址本身也可能含有凭据。
- 网络请求会发往所选 API、RSS 提供方、镜像或代理。镜像和代理属于独立的信任边界，
  已认证请求可能携带 Token；BitTorrent 还会与 Tracker 和对等节点通信。
- 日志会过滤部分常见凭据字段，但仍可能包含 URL、本地路径及其他个人信息。
  Windows 崩溃转储可能包含进程内存。发送附件前请检查内容，必要时通过私下渠道提供
  转储，不要在公开 Issue 中上传整个应用数据目录。

不要提交 `.env`、`.dart-define.json`、`build_config.json`、私钥签名证书
（`*.pfx`、`*.p12`）、签名密码或真实账号凭据。Release 提供的公钥 `.cer` 证书
不含私钥。若凭据已经泄露，请通过签发该凭据的服务撤销或轮换。
