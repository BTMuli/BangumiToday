# AnimeJaNai ONNX 超分

更新：2026-10-08。两档 AI 超分、TensorRT 帧桥、组件安装、引擎预编译和
benchmark 推荐已接入。隔离功能验证已有记录，完整播放器与发行环境仍待验收。

## 1. 当前行为与范围

Windows x64 内置播放器提供以下两档，沿用 `playbackUpscaleMode` 保存偏好：

| 选项 | 模型 | 滤镜 slot |
|---|---|---|
| AI 流畅 | AnimeJaNai HD V3.1 Standard Performance | 1 |
| AI 高质量 | AnimeJaNai HD V3.1 Standard Balanced | 2 |

- 默认 AI 后端为 TensorRT。要求实际播放显卡为 NVIDIA，架构属于
  SM89 / SM90 / SM100 / SM120，驱动支持 CUDA 13.4 或更高版本，组件与引擎就绪。
  设置页检测结果只是配置参考，原生端另核对实际 D3D11 / CUDA adapter。
- 当前输入契约为 SDR、BT.709 limited、NV12 / P010、无旋转、方形像素；
  输入不超过 1920×1080，模型固定放大 2 倍，可见输出不超过 3840×2160。
  最终纹理按视口计算，由 mpv 缩放模型输出；无需放大或不满足契约时普通播放。
- 组件安装由用户在设置页主动发起，选择档位不触发下载。配置完成后在播放器
  勾选“启用 TensorRT”，再选择 AI 档位。下载、编译均支持取消与重试。
- 引擎准备期间普通播放；准备、推理或性能检查失败时恢复普通播放。
  DirectML 仅保留显式 `backend=directml` 开发诊断，不参与自动回退。
- 普通播放、Anime4K、AI 共用 `hwdec=d3d11va`。切档只调整滤镜与纹理，
  不修改硬解、不重开媒体、不追加 `seek 0`；AI 与 Anime4K 不同时运行。
- HDR、macOS AI、任意模型导入、Sharp / SD 模型、串联模型、RIFE 和
  4:4:4 输出暂不在范围内。AMD / Intel 可使用普通播放与 Anime4K。

## 2. 实现与资源

帧路径为 `mpv D3D11 解码 → GPU RGB / FP16 张量 → TensorRT →
D3D11 NV12 / P010 → mpv / ANGLE → Flutter 纹理`，像素不经 CPU 回读。
字幕和控件在模型处理后合成；Dart 负责偏好、滤镜调度、状态及失败恢复。
原生端已加入共享上下文保护、CUDA Graph 与异步 GPU 计时，详细契约和
隔离性能记录见[原生实现说明](../../windows/playback/inference/README.md)。

### 固定版本与分发

| 部分 | 当前版本 / 来源 | 分发方式 |
|---|---|---|
| 模型 | HD V3.1 Standard，固定上游源码与文件哈希 | 主包内置两个 ONNX |
| mpv | JaNai fork `d6d93599d5`，发行包 `2026-10-07-d6d93599d5` | 主包；当前预编译包为 GPL，LGPL 构建待落实 |
| 推理桥 | 项目自有 aji ABI v8 | 主包 `aji.dll` |
| ORT / DirectML | 1.24.4 / 1.15.4 | 主包，保留诊断路径 |
| TensorRT / CUDA | 11.3.0.99 / 13.4，上游 AnimeJaNai 3.7.0 固定归档 | 用户选装公共包与当前 SM 包 |

版本、文件大小、SHA-256 和来源以
[基础依赖锁](../../windows/playback/inference/dependencies.lock.json)、
[组件锁](../../windows/playback/inference/trt-components.lock.json)及
[SDK 锁](../../windows/playback/inference/trt-sdk.lock.json)为准，文档不重复维护哈希表。
主包同时包含模型、许可、组件清单与应用本地 CRT；不包含 NVIDIA 大组件和驱动。
开发构建与发布流水线均通过准备脚本、CMake 和 bundle 校验接入固定资源。

### 安装与引擎缓存

- 当前选装源为上游 3.7.0 `.7z`，由系统 `tar.exe` 解压。支持字节进度、
  Range / ETag 续传、SHA-256、逐文件校验、跨窗口安装锁和 staging 原子发布；
  损坏安装目录通过事务修复，失败或取消不发布半成品。
- 资源写入 `%LOCALAPPDATA%/BangumiToday/playback-tensorrt/11.3.0.99/sm<架构>`，
  引擎位于同一数据根目录的 `engines`。不改写 MSIX 安装目录或系统 SDK。
- 组件安装后依次准备 `720p / 1080p × AI 流畅 / AI 高质量` 共四个引擎；
  预编译与播放共用缓存，已有结果直接复用，其他输入尺寸首次播放时按需构建。
  编译显示阶段与日志，没有可靠进度时不显示百分比。
- 引擎缓存按模型、尺寸、GPU、驱动、运行库和构建参数区分，校验与预热后
  原子发布；构建有 GPU 锁、超时和取消，活动租约阻止清理。组件准备完成后
  可离线播放，清除引擎缓存后可用已安装组件离线重建。

## 3. 推荐档位与性能保护

推荐采用 [AnimeJaNai 社区 benchmark](https://benchmarks.animejan.ai/) 的
[公开 JSON](https://benchmarks.animejan.ai/benchmarks.json)。主包快照包含
59 份已核实的 3.4～3.7 版本 TensorRT 样本，数据生成于 2026-10-07。
设置页支持手动更新和离线缓存，更新失败保留已有数据；显卡匹配在本机完成。

- Performance / Balanced 分别映射 AI 流畅 / AI 高质量，不使用上游 Quality 档。
  按完整 GPU 型号匹配，保留 Ti、SUPER、Laptop 与显存后缀。
- 设置页展示当前显卡的 720p / 1080p、24 fps 参考。播放器按实际播放显卡、
  当前视频轨道、解码尺寸、源帧率与倍速更新推荐，避开 `auto` / `no` 占位轨道
  和滤镜输出的 2 倍尺寸；推荐直接标在对应选项标题后。
- 同型号取最低实测 FPS，满足 `benchmark FPS >= 2 × 源 fps × 播放倍率`
  时优先推荐最高档。未测尺寸使用能覆盖输入的 720p / 1080p 测试尺寸，
  不按像素外推；`-1` 表示过慢或失败，包含此类样本的档位暂不推荐。
- 未知型号、参数缺失或余量不足时给出说明，不猜测档位或帧率。
  推荐不自动启用 TensorRT、下载组件或修改用户选择。
- benchmark 使用 `--vo=null` 离屏计时，不包含本项目解码和完整渲染成本，
  仅供初始选档，不能替代实际播放验收。

运行时另监控 GPU 帧预算和 mpv VO 丢帧。连续三个有效窗口超预算或丢帧率
超过 1% 时恢复普通播放；暂停、seek、准备期与无效样本不计入。切换倍速
重置统计并给予稳定期，性能降级后降低倍速可自动重试；模型、设备或恢复失败
仍需主动重试。状态、失败原因和准备日志已接入设置页与视频信息面板。

## 4. 验证与剩余工作

已记录的隔离验证覆盖模型与帧契约、NV12 / P010、padding / 裁剪、
D3D11 / CUDA 帧桥、ANGLE EGLStream、上下文并发与资源回收；组件下载、
续传、校验、安装事务、取消、引擎缓存和推荐逻辑已有非 UI 验证。
SM90 / SM100 / SM120 已纳入资源选择与校验，真实显卡推理验收仍待完成。
隔离速度和逐帧像素一致性不代表 Flutter 播放器端到端验收通过。

剩余事项按以下顺序推进：

1. **真实播放**：确认解码、推理与 ANGLE 使用同一 device；覆盖两档、
   720p / 1080p、8 / 10-bit SDR、字幕音轨、暂停切档、seek、倍速、重开与连播，
   验证画质、PTS 和普通播放恢复。
2. **性能与故障**：连续播放至少 10 分钟，目标为相对普通播放的 VO 丢帧增量
   ≤ 0.1%、持续 A/V 偏差 ≤ 50 ms，无黑屏或资源持续增长；验证超预算降级、
   显存不足、设备移除和恢复失败。补齐其他声明架构的真实 GPU 验收。
3. **组件管理**：补充资源移除入口、项目托管的固定组件包与完整许可材料。
   已有上游锁定归档方案继续使用，不把这些事项写成已交付。
4. **发行**：落实固定 LGPL libmpv 构建，完成模型及第三方许可与来源清单；
   覆盖干净 Windows、中文 / 空格路径、只读安装目录、断网、损坏资源、
   ZIP / MSIX / Store，以及主包体积与安装空间验收。

人工播放和完整构建由开发者发起；文档中的待办不自动授权启动、构建或发布。
