# Gitmoji 选择边界

按提交的主要目的比较候选。下表针对容易被通用图标覆盖的场景，不是完整目录；其他场景查阅 [Gitmoji 官方目录](https://gitmoji.dev/) 或 [官方 JSON 定义](https://gitmoji.dev/api/gitmojis)。语义核对日期：2026-10-07。

| 当前变更的主要目的 | 候选与选择边界 |
| --- | --- |
| 修复问题 | `🐛` 表达通常的行为错误修复；明确的严重紧急热修复才用 `🚑️`；简单、非关键问题的小修补可用 `🩹`；专门消除编译器或 linter 警告用 `🚨`。提交很小不等于非关键。 |
| 调整界面或交互 | 外观和样式用 `💄`；操作流程、可用性用 `🚸`；响应式布局用 `📱`；无障碍用 `♿️`；动画和过渡用 `💫`。新增用户能力仍可用 `✨`，不能只因改了 UI 文件就用 `💄`。 |
| 整理代码或资源 | 行为不变的逻辑重构用 `♻️`；代码结构、格式整理用 `🎨`；模块边界或架构调整用 `🏗️`；单纯移动、重命名文件、路径或路由用 `🚚`。移动只是重构手段时按整体目的选择。 |
| 清理或废弃 | 删除已不可达、未使用的死代码用 `⚰️`；一般代码或文件删除用 `🔥`；标记废弃但暂时保留用 `🗑️`。修复问题时顺带删几行代码，不自动变成删除类提交。 |
| 文档、注释或文字 | 文档和 Agent/Skill 说明用 `📝`；源码注释用 `💡`；界面文案或字面量用 `💬`；翻译和本地化用 `🌐`；只纠正拼写用 `✏️`。Markdown 中的提交规则属于文档，不能仅因涉及工具就用 `🔧`。 |
| 配置、脚本或开发体验 | 配置文件用 `🔧`，不将它当“杂项”兜底；开发脚本用 `🔨`；主要改善开发者工作体验用 `🧑‍💻`；忽略规则用 `🙈`；功能开关用 `🚩`。按实际作用判断，文件扩展名不是结论。 |
| CI 与基础设施 | 新增、调整 CI 构建系统用 `👷`；修复失败的 CI 构建用 `💚`；部署环境等基础设施调整用 `🧱`。CI 不一律归为 `🧱` 或 `🔧`。 |
| 依赖变更 | 添加用 `➕`、移除用 `➖`、升级用 `⬆️`、降级用 `⬇️`、固定版本用 `📌`。锁文件随一项功能产生的必要更新，不要求拆成独立依赖提交。 |
| 外部接口或兼容 | 外部 API 已变化，适配调用端用 `👽️`；专门增加向后兼容用 `🦖`。首次接入 API 可属于 `✨`，修复自己解析错误可属于 `🐛`，不能一律算 API 适配。 |
| 数据库或类型 | 以数据库结构、迁移、查询设计为中心用 `🗃️`；种子数据用 `🌱`；专门增加、调整类型声明用 `🏷️`。新增功能涉及表结构，或 Bug 修复涉及类型，不必仅按实现层选图标。 |
| 日志与观测 | 新增、调整日志用 `🔊`；移除日志用 `🔇`；分析统计或埋点用 `📈`；健康检查用 `🩺`。普通调试日志不等于业务统计埋点。 |
| 安全与权限 | 修复安全、隐私漏洞用 `🔒️`；角色、授权或权限逻辑用 `🛂`；更新 secrets 用 `🔐`。一般登录功能或普通配置不自动属于安全修复。 |
| 行为与健壮性 | 新增用户能力用 `✨`；调整既有业务规则用 `👔`；主要增加输入校验用 `🦺`；捕获、处理错误用 `🥅`；离线支持用 `✈️`。修复既有错误时仍需比较 `🐛`，不要只按新增代码的形式选择。 |
| 性能或并发 | 主要改善性能用 `⚡️`；主要改变多线程或并发处理用 `🧵`。异步代码并不必然改善性能；修复并发错误时可以用 `🐛`。 |
| 发布与产物 | 版本发布或版本标记用 `🔖`；实际部署用 `🚀`；编译产物或包用 `📦️`；素材资源用 `🍱`。版本号更新不能一律用部署图标。 |
| 测试 | 实际提交新增、更新测试用 `✅`；专门添加失败测试用 `🧪`。仅运行验证或删除临时测试不构成测试类提交，是否保留测试文件按仓库规则处理。 |
| 破坏兼容 | 引入要求调用方迁移的破坏性变更用 `💥`，并在 subject 或正文中指出不兼容之处。内部重构不自动破坏兼容。 |

## 用实际目的复核

- `💚 修复 Windows 发布流水线的缓存路径`：目的是恢复失败的 CI 构建。
- `🔨 增加本地下载引擎诊断脚本`：交付的是开发脚本。
- `🚚 将播放路径工具移动到 core/utils`：只移动文件并调整引用。
- `⚰️ 移除未使用的旧播放属性解析器`：清理不再被调用的代码。
- `👽️ 适配上游 API 新的分页响应字段`：上游契约已经变化。
- `🚸 保持下拉框展开时的选择字段可见`：目的在于可用性。
- `🔊 为下载任务添加状态转换日志`：目的是增加日志。
- `📝 明确 Gitmoji 图标的选择规则`：更新的是说明文档。

这些是选择示例，不代表需要提交、拆分、改写历史或创建测试；执行权限和仓库规则仍按当前任务处理。
